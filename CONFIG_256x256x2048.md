# Config Changes for 256×256×2048 Dataset Generation

Exact parameters (file + line + value) that produce a **256×256 spatial ×
2048 time-bin** dataset of the motorbike `dataset/`, compared to the original
upstream code.

> You normally do **not** edit these by hand — `simulate_folder.ps1 dataset
> -HW 256 -TimeBin 2048 -Poses 5` patches them automatically. This doc is the
> reference for what those flags change, and for editing manually if needed.

---

## A. Resolution changes (the "256 size")

### A1. Spatial resolution → 256×256
**File:** `cuda-render/render/src/main.cpp`

| Line | Original (upstream) | This (256) |
|---|---|---|
| 72 | `int height = 256;` | `int height = 256;` |
| 73 | `int width = 256;` | `int width = 256;` |

Note: upstream default was already 256. (During testing it was set to 64/128;
for this dataset it is **256**.) For 512, set both to `512`.
Set automatically by `-HW 256`.

### A2. Temporal resolution → 2048 time bins
**File:** `cuda-render/render/src/display_6_render.cpp`

| Line | Original (upstream) | This (2048) |
|---|---|---|
| 7 | *(did not exist)* | `#define NTBIN 2048` &nbsp;← **new line added** after `#define TEN 6` |
| 63 | `int timebin = (TEN - TBE) * 100;` | `int timebin = NTBIN;` |
| 336 | `int timebin = (TEN - TBE) * 100;` | `int timebin = NTBIN;` |
| 773 | `..., width, maxsz, 100 * TEN, 100 * TBE);` | `..., width, maxsz, NTBIN, 0);` |

Upstream produced `(TEN-TBE)*100 = 600` bins. Now it is `NTBIN = 2048`.
Set automatically by `-TimeBin 2048`.

## B. Batch config (render the whole dataset, multiple poses)

**File:** `cuda-render/render/src/main.cpp`

| Line | Param | Original (upstream) | This (batch) | Meaning |
|---|---|---|---|---|
| 31 | `parentFlder` | `"../../data/bunny-model"` | `".../data/batch-models"` | input models folder |
| 33 | `parentSvFolder` | `"../../data/bunny-renders"` | `".../data/batch-raw"` | raw output folder |
| 44 | `definerot` | `true` | `false` | `false` = random poses per sample |
| 91 | `rendernum` | `1` | `337` | number of models to render |
| 115 | `rnum` | `1` | `5` | poses per model (`-Poses 5`) |

`definerot`/`rnum`/`rendernum` are set automatically: `-Poses N` sets `rnum`,
and `rendernum` is set to the number of prepared models. Paths are patched to
`data/batch-models` + `data/batch-raw` by `simulate_folder.ps1`.

## C. Unchanged (but relevant)

| File | Line | Value | Note |
|---|---|---|---|
| `main.cpp` | 76 | `int samplenum = 600;` | scan-direction sampling (unchanged) |
| `main.cpp` | 83 | `int blocksz = 40;` | tile-batch size. **For 512 on a small GPU, lower this** (e.g. 16) so the tile texture fits. On a 32 GB GPU, 40 is fine. |
| `display_6_render.cpp` | 5–6 | `TBE 0`, `TEN 6` | time window bounds (unchanged) |
| `copydata.cu` | 61 | `float tidx = depth * 100;` | **bin width = 0.01 m ≈ 33 ps** (unchanged). `NTBIN` changes the *count*, not the width. |

## D. Windows portability fixes (already applied, separate from resolution)

These make it build/run on Windows and are unrelated to resolution — see
`MIGRATION_GUIDE.md` for the exact diffs:
- `copydata.cu` line 5: `and` → `&&`
- `main.cpp`: `getFiles()` uses `std::filesystem`; `system("mkdir")` → `fs::create_directories`
- `display_6_render.cpp`: `#include <filesystem>`; `system("mkdir")` → `create_directories`

## E. Memory per resolution (device transient buffer = 4·T·H·W·3 bytes)

| Config | GPU buffer | Fits |
|---|---|---|
| 64×64×2048 | 0.09 GB | any GPU |
| 128×128×2048 | 0.38 GB | any |
| **256×256×2048** | **1.50 GB** | ≥ ~4 GB GPU ✅ |
| 512×512×2048 | 6.00 GB | ≥ 8–12 GB GPU (fits 32 GB easily) |

---

## F. Commands (what actually applies all of the above)

```powershell
# 256×256×2048, all models in dataset/, 5 poses each:
powershell -ExecutionPolicy Bypass -File cuda-render\simulate_folder.ps1 "dataset" -HW 256 -TimeBin 2048 -Poses 5 -OutName output-bikes-256

# 512×512×2048 (matches a 512-trained reconstruction model; needs a big GPU):
powershell -ExecutionPolicy Bypass -File cuda-render\simulate_folder.ps1 "dataset" -HW 512 -TimeBin 2048 -Poses 5 -OutName output-bikes-512
```

Output: `output-bikes-256\0\<hash>\shine_..\` — 6 bike files per sample
(confocal-0 hdr+png, depth-0 hdr+png, video-confocal + video-confocalspad mp4).
